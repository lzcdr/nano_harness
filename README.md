
# NANO_HARNESS - МУЛЬТИАГЕНТНЫЙ ФРЕЙМВОРК ДЛЯ ЛОКАЛЬНОГО ЗАПУСКА ИИ-АГЕНТОВ

## ОПИСАНИЕ

Проект nano_harness позволяет запускать несколько независимых ИИ-агентов на локальной машине. Каждый агент работает как HTTP-сервер, принимает запросы, взаимодействует с большой языковой моделью (через OpenAI-совместимый API) и может вызывать инструменты: выполнять код на языке Rhai, обращаться к локальному файловому хранилищу, а также напрямую вызывать других агентов.

Агенты могут обмениваться данными через общее хранилище, а также отправлять друг другу запросы через функцию call_agent, доступную внутри Rhai-кода. Это позволяет строить цепочки вызовов и распределять задачи между специализированными агентами.

Проект ориентирован на однопользовательское локальное использование и рассматривается как прототип для экспериментов с мультиагентными системами.

## АРХИТЕКТУРА

В состав входят три основных компонента:

1. Движок общения (engine.rs) - отвечает за обмен сообщениями с LLM, управление историей диалога, поддержку потоковой передачи (streaming) и не-потокового режима, подсчёт метрик (токены, стоимость) и ограничение бюджета.

2. Агенты - HTTP-серверы, запускаемые отдельными процессами для каждого агента из конфигурации. Агент принимает запросы, выполняет логику (в том числе вызовы инструментов) и возвращает ответ. Поддерживаются два режима: stateless (каждый запрос обрабатывается с чистым контекстом) и stateful (контекст сохраняется в рамках сессии с идентификатором).

3. Локальное хранилище - HTTP-сервер, предоставляющий доступ к файловой системе и семантическому поиску. Файлы хранятся в директории .local_storage/<имя хранилища>. Для поиска используется векторный индекс на основе модели эмбеддингов (по умолчанию paraphrase-multilingual-MiniLM-L12-v2) и библиотеки HNSW.

Все сервисы взаимодействуют по HTTP с аутентификацией через токены Bearer.

## ТРЕБОВАНИЯ

- Установленный Rust (стабильная версия).
- Доступ к API языковой модели (например, Polza.ai или любой другой OpenAI-совместимый сервис).
- Модель эмбеддингов для работы семантического поиска (описано ниже).

## ПОДГОТОВКА МОДЕЛИ ЭМБЕДДИНГОВ

Для работы семантического поиска необходимо скачать модель, которая будет преобразовывать тексты в векторные представления. По умолчанию используется модель sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2.

Почему выбрана именно эта модель:
- Мультиязычная, хорошо работает с русским и английским языками.
- Компактная (около 118 миллионов параметров), быстро работает на CPU.
- Даёт приемлемое качество для поиска похожих текстов.

Вы можете использовать любую другую модель архитектуры BERT, совместимую с библиотекой candle. Для этого потребуются файлы config.json, model.safetensors (или сконвертированный pytorch_model.bin) и tokenizer.json.

Скачайте модель с Hugging Face: https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2

Необходимые файлы:
- config.json
- model.safetensors (если отсутствует, конвертируйте из pytorch_model.bin)
- tokenizer.json

Разместите эти файлы в директории .models/paraphrase-multilingual-MiniLM-L12-v2/ внутри проекта. Путь можно изменить в конфигурации.

## СБОРКА ПРОЕКТА

Выполните команды:

```bash
git clone <репозиторий>
cd nano_harness
cargo build --release
```

## ЗАПУСК

Сначала запустите сервер локального хранилища:

```bash
cargo run --bin local_storage_http_server -- --config config.toml
```

Затем для каждого агента (имя берётся из конфигурации) запустите отдельный процесс:

```bash
cargo run --bin agent_server -- --agent-name assistant --config config.toml
```

Если агентов несколько, повторите команду с другим именем. Все агенты и хранилище должны быть запущены одновременно.

Для интерактивного чата с моделью можно использовать основную программу (не обязательна для работы агентов):

```bash
cargo run -- --config config.toml
```
В этом режиме поддерживаются команды:
- /clear - очистить контекст
- /metrics - показать метрики
- /system <текст> - изменить системный промпт
- /fix - закрепить последнюю пару сообщений в префиксе
- /exit - выход

## КОНФИГУРАЦИЯ (config.toml)

Файл конфигурации состоит из нескольких секций.

### ГЛОБАЛЬНЫЕ ПАРАМЕТРЫ (находятся в корне)

- api_key - API-ключ для языковой модели. Может быть переопределён переменной окружения POLZA_API_KEY или аргументом командной строки. Тип: строка.
- base_url - базовый URL API (по умолчанию https://polza.ai/api/v1). Тип: строка.
- model - идентификатор модели (например, "google/gemini-3.1-flash-lite"). Тип: строка.
- temperature - температура генерации (от 0 до 2). Тип: число с плавающей точкой.
- max_tokens - максимальное количество токенов в ответе модели. Тип: целое число.
- top_p - параметр top_p для сэмплирования. Тип: число с плавающей точкой.
- stream - использовать потоковый режим (true/false). Тип: логический.
- reasoning_effort - уровень "размышлений" для моделей, поддерживающих эту функцию (low, medium, high). Тип: строка.
- max_cost_rub - максимальный бюджет в рублях. При превышении запросы к API прекращаются. Тип: число с плавающей точкой.
- prefix_message_count - количество первых пар сообщений (запрос-ответ), которые всегда сохраняются в контексте (долговременная память). Тип: целое число.
- tail_message_count - количество последних пар сообщений, сохраняемых в скользящем окне. Тип: целое число.
- system_prompt - системный промпт по умолчанию. Используется в CLI и агентами, если у агента не задан свой. Тип: строка.
- rhai_timeout_sec - таймаут выполнения Rhai-кода в секундах (для CLI). Тип: целое число.
- skill_mode - режим работы со скиллами: "auto" (автоматический), "manual" (ручной), "off" (отключено). По умолчанию "auto". Тип: строка.
- skill_semantic_threshold — порог косинусного расстояния при поиске скиллов. Чем меньше значение, тем более похожи тексты. Если расстояние больше порога, скилл не считается подходящим. По умолчанию 0.5.
- skill_min_code_length - минимальная длина Rhai-кода (в символах после удаления комментариев и пустых строк), при которой код считается достаточно сложным для сохранения как скилл. По умолчанию 100. Тип: целое число.
### СЕКЦИЯ [vector_db]

Описывает параметры векторного индекса.

- model_path - путь к директории с файлами модели эмбеддингов. Тип: строка.
- tokenizer_path - путь к файлу tokenizer.json. Тип: строка.
- chunk_size - максимальный размер фрагмента текста (чанка) в байтах, на которые разбиваются файлы при индексации. Тип: целое число.
- chunk_overlap - перекрытие между соседними чанками в байтах. Тип: целое число.
- top_k - количество результатов, возвращаемых при семантическом поиске по умолчанию. Тип: целое число.

### СЕКЦИЯ [local_storage_http_server]

Параметры HTTP-сервера хранилища.

- bind_addr - адрес и порт, на котором запускается сервер (например, "127.0.0.1:8080"). Тип: строка.
- storage_name - имя поддиректории внутри .local_storage/, где будут храниться файлы. Тип: строка.
- auth_token - токен для аутентификации запросов к хранилищу. Тип: строка.

### СЕКЦИЯ [[agents]]

Массив агентов. Каждый агент описывается набором полей.

- name - уникальное имя агента. Используется при запуске и для вызова из других агентов. Тип: строка.
- bind_addr - адрес и порт HTTP-сервера агента. Тип: строка.
- auth_token - токен для доступа к API агента. Тип: строка.
- timeout_sec - таймаут HTTP-запросов агента к LLM и хранилищу (секунды). Тип: целое число.
- max_iterations - максимальное количество циклов "запрос модели -> выполнение инструментов" в рамках одной обработки. Тип: целое число.
- tools - список разрешённых инструментов, например ["run_code", "local_storage"]. Тип: массив строк.
- system_prompt - системный промпт для данного агента. Если не указан, используется глобальный. Тип: строка.
- api_key - API-ключ для языковой модели (можно индивидуальный). Тип: строка.
- base_url - базовый URL API для этого агента. Тип: строка.
- model - модель для этого агента. Тип: строка.
- temperature - температура. Тип: число с плавающей точкой.
- max_tokens - максимум токенов. Тип: целое число.
- top_p - top_p. Тип: число с плавающей точкой.
- stream - потоковый режим (true/false). Тип: логический.
- prefix_message_count - количество первых пар сообщений, сохраняемых в контексте. Тип: целое число.
- tail_message_count - количество последних пар сообщений. Тип: целое число.
- reasoning_effort - уровень размышлений. Тип: строка.
- rhai_timeout_sec - таймаут Rhai-кода для этого агента (секунды). Тип: целое число.
- agent_call_timeout_sec - таймаут вызова другого агента через функцию call_agent из Rhai-кода (секунды). Если не указано, используется значение 120. Тип: целое число.
- agent_type - режим работы: "stateless" или "stateful". Тип: строка.
- session_ttl_secs - время жизни сессии в секундах для stateful-агента. По истечении сессия удаляется (при следующем обращении). Тип: целое число.
- skill_mode - режим работы со скиллами: "auto" (автоматический), "manual" (ручной), "off" (отключено). По умолчанию "auto". Тип: строка.
- skill_semantic_threshold — порог косинусного расстояния при поиске скиллов. Чем меньше значение, тем более похожи тексты. Если расстояние больше порога, скилл не считается подходящим. По умолчанию 0.5.
- skill_min_code_length - минимальная длина Rhai-кода (в символах после удаления комментариев и пустых строк), при которой код считается достаточно сложным для сохранения как скилл. По умолчанию 100. Тип: целое число.

## HTTP API ХРАНИЛИЩА

Все запросы к хранилищу требуют заголовок Authorization: Bearer <auth_token>.
Базовый адрес: http://<bind_addr из конфигурации>.

Операции с файлами:

- GET /files?path=<путь> - возвращает содержимое файла.
- POST /files?path=<путь>, тело запроса - текст файла. Создаёт или перезаписывает файл, обновляет векторный индекс. Возвращает пустое тело (статус 200 OK).
- DELETE /files?path=<путь> - удаляет файл и связанные записи из индекса.

Операции с директориями:

- POST /dirs?path=<путь> - создаёт директорию (включая промежуточные) и автоматически создаёт в ней служебные файлы .about и .summary, если их нет.

Списки и обход:

- GET /list?path=<путь> - возвращает JSON-массив объектов для элементов директории. Для файлов: {name, path, size}, для папок: {name, path}.
- GET /walk?path=<путь> - рекурсивный обход директории, возвращает JSON-массив таких же объектов.

Поиск:

- GET /search?query=<текст>&top_k=<число> - семантический поиск. Возвращает JSON-массив объектов: {file_path, chunk_index, distance, content_fragment}.
- GET /search_name?pattern=<подстрока> - поиск файлов и папок по имени. Возвращает JSON-массив путей.

Мета-файлы:

- GET /about?path=<путь> - читает содержимое файла .about в указанной директории.
- POST /about?path=<путь>, тело - текст. Записывает .about.
- GET /summary?path=<путь> - читает .summary.
- POST /summary?path=<путь>, тело - текст. Записывает .summary.

## HTTP API АГЕНТОВ

Каждый агент запускает HTTP-сервер. Все запросы требуют заголовок Authorization: Bearer <auth_token агента>.

Основной эндпоинт:

- POST /agent/run

Тело запроса - JSON со следующими полями:

- prompt - обязательное, строка. Задача или сообщение пользователя.
- max_iterations - необязательное, целое число. Переопределяет максимальное количество итераций для этого запроса.
- tools - необязательное, массив строк. Переопределяет список разрешённых инструментов.
- system_prompt - необязательное, строка. Переопределяет системный промпт для этого запроса (только для stateless-режима).
- session_id - необязательное, строка. Для stateful-агента указывает идентификатор сессии. Если сессия существует, контекст будет продолжен, иначе создастся новая сессия с этим идентификатором.

Ответ - JSON со следующими полями:

- status - строка, обычно "completed" или "failed".
- result - строка, финальный ответ модели.
- reasoning - строка или null, если модель возвращала промежуточные рассуждения.
- tool_calls_log - массив объектов с информацией о вызванных инструментах: {name, arguments, result}.
- metrics - объект с метриками: {prompt_tokens, completion_tokens, cost_rub, api_calls_count}.
- error - строка или null, если произошла ошибка.
- session_id - строка или null, идентификатор сессии (для stateful-агента возвращается).

## СИСТЕМА СКИЛЛОВ

Система скиллов предназначена для накопления и повторного использования успешных решений задач. Скилл представляет собой файл, содержащий полную инструкцию (описание задачи) и готовый Rhai-код, который агент может использовать при похожих запросах.

Хранение: все скиллы размещаются в директории .skills внутри хранилища. Для каждого скилла создаются два файла:
- skill_agent_<имя_агента>_<название>_<timestamp>.txt - полный файл скилла, внутри секции SKILL, FOR, DESCRIPTION, INSTRUCTION, RHAI_CODE.
- skill_agent_<имя_агента>_<название>_<timestamp>_description.txt - файл с кратким описанием (description) для семантического поиска.

Также ведётся каталог skills_catalog.json, в котором для каждого скилла хранится запись: имя файла, имя описания, имя агента, краткое описание, статистика успешных/неуспешных использований, хэш AST-кода, дата создания.

Режимы работы:
- auto (по умолчанию): обёртка агента автоматически управляет скиллами. Перед выполнением запроса она ищет подходящий скилл (сначала среди скиллов, созданных этим агентом, затем среди всех) по семантической близости описания к текущему запросу. Если найден скилл с расстоянием меньше skill_semantic_threshold (т.е. достаточно похожий) и с наилучшей статистикой успешности, его содержимое добавляется в контекст агента. После успешного выполнения кода Rhai (длина кода не меньше skill_min_code_length, и код уникален) обёртка генерирует название и описание скилла через LLM (используя те же настройки агента), затем сохраняет новый скилл.
- manual: агент сам управляет скиллами через доступные Rhai-функции (skill_search, skill_load, skill_save, skill_list, skill_record_usage). Обёртка не вмешивается.
- off: функции скиллов отключены, автоматика не работает.

В ручном режиме агент может вызывать следующие Rhai-функции (доступны только при skill_mode = "manual"):
- skill_search(query: string) -> string - ищет подходящий скилл по текстовому запросу, возвращает JSON с лучшим кандидатом и оценкой.
- skill_load(skill_name: string) -> string - читает полный файл скилла по части имени или названию.
- skill_save(skill_name: string, description: string, prompt: string, rhai_code: string) -> string - сохраняет новый скилл. Параметры: название, описание, исходный промпт, код Rhai. Возвращает "OK" или сообщение об ошибке.
- skill_list() -> string - возвращает каталог скиллов в формате JSON.
- skill_record_usage(skill_name: string, success: bool) -> string - обновляет статистику использования указанного скилла (успех или неудача).

## ФУНКЦИИ, ДОСТУПНЫЕ ИЗ RHAI-КОДА

Внутри инструмента run_code агент выполняет скрипт на языке Rhai. В этом скрипте доступны следующие встроенные функции.

Базовые функции:

- get_time() -> string - возвращает текущее время в формате "YYYY-MM-DD HH:MM:SS".
- get_weather(city: string) -> string - возвращает строку с заглушкой погоды для указанного города.

Функции хранилища (все принимают и возвращают строки):

- storage_read_file(path: string) -> string - читает файл и возвращает его содержимое.
- storage_write_file(path: string, content: string) -> string - записывает файл. Возвращает "OK" или описание ошибки.
- storage_delete_file(path: string) -> string - удаляет файл. Возвращает "OK" или ошибку.
- storage_create_dir(path: string) -> string - создаёт директорию. Возвращает "OK" или ошибку.
- storage_list_dir(path: string) -> string - возвращает JSON-строку с массивом объектов {name, path, size} для элементов директории.
- storage_walk(path: string) -> string - рекурсивный обход, возвращает JSON-строку с массивом объектов.
- storage_search_by_name(pattern: string) -> string - поиск по имени, возвращает JSON-строку с массивом путей.
- storage_search_similar(query: string, top_k: int) -> string - семантический поиск, возвращает JSON-строку с массивом объектов {file_path, distance, content_fragment}.
- storage_read_about(path: string) -> string - читает .about в указанной директории.
- storage_write_about(path: string, content: string) -> string - записывает .about.
- storage_read_summary(path: string) -> string - читает .summary.
- storage_write_summary(path: string, content: string) -> string - записывает .summary.

Функция вызова других агентов:

- call_agent(name: string, prompt: string) -> string - отправляет запрос другому агенту по его имени (из конфигурации). Возвращает строку с результатом (поле result из ответа агента) или сообщение об ошибке. Агент не может вызывать сам себя - в этом случае вернётся ошибка. Таймаут вызова задаётся параметром agent_call_timeout_sec в конфигурации агента (по умолчанию 120 секунд).

Функции скиллов (доступны только при skill_mode = "manual"):

- skill_search(query: string) -> string
- skill_load(skill_name: string) -> string
- skill_save(skill_name: string, description: string, prompt: string, rhai_code: string) -> string
- skill_list() -> string
- skill_record_usage(skill_name: string, success: bool) -> string

## ОГРАНИЧЕНИЯ ПРОТОТИПА

- Проект предназначен для локального однопользовательского использования. Не рассчитан на многопользовательскую безопасную эксплуатацию.
- Все серверы работают без TLS, поэтому не рекомендуется запускать их на публичных интерфейсах.
- Хранилище использует глобальный Mutex, что сериализует все операции. При интенсивной нагрузке возможны задержки.
- Векторный индекс перестраивается не полностью автоматически: если файл изменён вручную (не через API хранилища), его нужно перезаписать через API для обновления индекса.
- Логи чатов сохраняются в директорию chats/ и не имеют автоматической ротации.
- Ограничение на количество чанков в индексе HNSW задано как 100000, что соответствует примерно 50 МБ текстовых данных.
- В Rhai-коде установлены ограничения: максимальное количество операций 10000, глубина вызовов 32, максимальный размер строки 10 КБ. Это может ограничивать обработку больших ответов хранилища или агентов.
- Вызов другого агента из Rhai выполняется синхронно с таймаутом, заданным в конфигурации (agent_call_timeout_sec, по умолчанию 120 секунд). При длинных цепочках вызовов может не хватить общего времени rhai_timeout_sec.

## ПРИМЕРЫ ЗАПРОСОВ CURL

Запрос к агенту (stateless):

```bash
curl -X POST http://127.0.0.1:8081/agent/run \
  -H "Authorization: Bearer agent_token_1" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Прочитай файл hello.txt и верни его содержимое"}'
```

Запрос к stateful-агенту с созданием сессии:

```bash
curl -X POST http://127.0.0.1:8081/agent/run \
  -H "Authorization: Bearer agent_token_1" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Запомни, что меня зовут Алексей", "session_id": "my_session_1"}'
```

Продолжение сессии:

```bash
curl -X POST http://127.0.0.1:8081/agent/run \
  -H "Authorization: Bearer agent_token_1" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Как меня зовут?", "session_id": "my_session_1"}'
```

Запись файла в хранилище:

```bash
curl -X POST "http://127.0.0.1:8080/files?path=test.txt" \
  -H "Authorization: Bearer secret" \
  -d "Привет, мир!"
```

Чтение файла:

```bash
curl "http://127.0.0.1:8080/files?path=test.txt" \
  -H "Authorization: Bearer secret"
```

Семантический поиск:

```bash
curl "http://127.0.0.1:8080/search?query=приветствие&top_k=3" \
  -H "Authorization: Bearer secret"
```

Получение списка файлов в директории:

```bash
curl "http://127.0.0.1:8080/list?path=" \
  -H "Authorization: Bearer secret"
```
